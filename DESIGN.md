## 2. MCP tools

General rules: every tool returns **both** `content` (short text Alexa can speak from) and `structuredContent` (typed JSON). Use the annotations `readOnlyHint` and `destructiveHint` / `idempotentHint`. Descriptions say *when* to use the tool, because Alexa's reasoning picks tools from descriptions. Spoken text is ≤ 40 words per incident, with no IDs read aloud.

### `get_active_incidents` (readOnly; UI: `ui://nightwatch/incidents.html`)
Use when the user asks what's going on, whether anything is wrong, or for a status overview.
```jsonc
// input
{ "scope": "all|home|work", "min_severity": "critical|high|moderate|low", "limit": 3 }   // all optional; defaults all / low / 3 (max 5)
// output.structuredContent
{
  "as_of": "2026-10-21T10:02:11Z",
  "household": "Demo Household",
  "spoken_overview": "Two things. A red flag wind warning for your county…",
  "incidents": [{
    "id": "inc_01J…", "kind": "hazard|prod", "title": "Red Flag Warning",
    "severity": "high", "status": "open|acknowledged|escalated|resolved",
    "started_at": "…", "spoken_summary": "…", "top_action": "Keep windows closed",
    "evidence_preview": ["NWS warning, county-wide", "AQI 78 (moderate)"],
    "escalation_due_at": "…|null", "replay": true, "replay_original_time": "…|null"
  }]
}
```

### `explain_incident` (readOnly)
Use when the user asks why, how you know, or for more detail. Defaults to the top-ranked incident. Also accepts a fuzzy reference ("the fire one").
```jsonc
{ "incident_id": "string?", "reference": "string?", "depth": "brief|full" }
→ { "id", "title", "what_happened", "what_it_means_for_you",
    "evidence": [{ "type": "deploy_proximity", "detail": "Latency rose 4 min after deploy d-AB12 (v42→v43)", "weight": 0.6, "source_url": "…" }],
    "confidence": "high|medium|low", "timeline": [{ "at", "event" }], "sources": ["NWS", "AirNow"] }
```

### `get_runbook` (readOnly)
```jsonc
{ "incident_id": "string?" } → { "runbook_id", "title", "next_step": "…", "steps": [{ "n", "action", "why", "done": false }] }
```

### `acknowledge` (idempotent, not destructive)
```jsonc
{ "incident_id": "string?" } → { "id", "status": "acknowledged", "acked_at", "escalation_cancelled": true }
```

### `escalate` (not readOnly)
```jsonc
{ "incident_id": "string?", "reason": "string?" } → { "id", "escalated_to": "Priya (roommate)", "channels": ["push","email"], "status": "escalated" }
```

### `notify_contact` (not readOnly; Alexa may confirm)
Use when the user asks to tell, text, or alert a person about an incident.
```jsonc
{ "contact": "roommate|<name>", "incident_id": "string?", "note": "string?" }
→ { "delivered": true, "contact": "Priya", "channels": ["push","email"], "message_preview": "Red Flag Warning for … keep windows closed. —Night Watch" }
```
The message body is generated from the incident record (deterministic template), not free LLM text. Rate limit: 3 per contact per hour.

Stretch: `rollback_deploy({service, incident_id, confirm:boolean})`, which refuses unless `confirm=true`.

Errors: return MCP tool errors with an actionable message ("I couldn't find an incident matching 'the fire one'. There are 2 active: …"). Never return HTTP 500 for user mistakes.

## 3. DynamoDB single-table model (`nightwatch`)

| Entity | PK | SK | Notes |
|---|---|---|---|
| Household | `HH#<hid>` | `PROFILE` | name, lat/lon, NWS zone/county, tz, ack_timeout_s |
| Contact | `HH#<hid>` | `CONTACT#<cid>` | name, aliases ["roommate"], channels {ntfy_topic, email}, escalation_order |
| Escalation policy | `HH#<hid>` | `POLICY#<kind>` | steps [{after_s, contact_id}] |
| Incident | `INC#<iid>` | `META` | full Incident doc; **GSI1PK=`HH#<hid>#ACTIVE`, GSI1SK=`<sevRank>#<startedAt>`** (sparse: removed on resolve) |
| Incident event | `INC#<iid>` | `EVT#<ts>#<eid>` | signal_added / summarized / acked / notified / escalated |
| Signal dedupe | `SIG#<source>#<extId>` | `META` | conditional put, TTL 7 d |
| Deploy record | `SVC#<name>` | `DEPLOY#<endedAt>#<deployId>` | for proximity queries (Query SK between) |
| Open incident by key | `HH#<hid>` | `OPENKEY#<correlationKey>` | → iid; groups new signals into an existing incident |
| User link (auth stretch) | `USER#<sub>` | `LINK` | → hid |

Access patterns: list active incidents for a household (GSI1 Query, limit 5); get incident + timeline (Query PK=INC#); find deploys of a service in a window (Query SK range); dedupe a signal (conditional Put); attach a signal to an open incident (Get OPENKEY then TransactWrite).
On-demand capacity, PITR off (demo), TTL attribute `expires_at`.

### Incident (pydantic)
`id, household_id, kind, title, severity, status, started_at, updated_at, correlation_key, signals[{source, external_id, observed_at, summary, url}], evidence[Evidence], spoken_summary, detail_summary, recommended_actions[], runbook_id, acked_by, acked_at, escalation_schedule_name, replay, replay_original_time, summarizer {model, latency_ms, fallback_used}`

## 4. Terraform layout

```
infra/bootstrap/          S3 state bucket (versioned, use_lockfile), Budget alarm
infra/modules/
  data/                   DynamoDB table + GSI1 + TTL
  mcp_server/             Lambda (arm64, Lambda Web Adapter layer, PC=1 via alias), HTTP API, routes /mcp + /.well-known/*, log group, IAM (table RW only)
  ingest/                 EventBridge bus, Scheduler schedules, ingester Lambdas, SSM params (AirNow key), rules for CloudWatch/CodeDeploy events
  triage/                 triage Lambda, Bedrock InvokeModel permissions (model ARN-scoped), rule on bus
  escalation/             Scheduler group + role, timer Lambda
  notify/                 SNS topic, SES identity, notifier Lambda, SSM ntfy topic
  demo_service/           checkout Lambda + alias + HTTP API, CodeDeploy app/group, loadgen schedule, p95 alarm
  static_site/            S3 + CloudFront (OAC) for privacy/terms/icons/carousel
  observability/          dashboard (tool p95, errors, ingest lag), alarms, X-Ray
  auth/ (optional)        Cognito user pool, app client (PKCE, refresh), hosted domain, metadata route
infra/envs/dev/main.tf    wires modules; outputs MCP URL, site URLs
```
Conventions: one `locals { tags = {...} }` per env, `default_tags` on the provider, every module has `README.md` + `variables.tf` with descriptions, `tflint` + `terraform validate` in CI. Lambda zips come from `make build` (uv export → pip install --platform manylinux2014_aarch64).

## 5. Stateless transport on Lambda

- `MCPServer(..., extensions=[apps])`; app via `streamable_http_app(stateless_http=True, json_response=True)` (exact v2 signature: VERIFY in the SDK docs).
- Lambda Web Adapter runs `uvicorn nightwatch.app:asgi --port 8080`; readiness check on `/healthz`.
- GET `/mcp` → 405. DELETE → 405/200 no-op. No session IDs needed. If the SDK sends `Mcp-Session-Id` in stateless mode, that's harmless.
- Accept `protocolVersion` 2025-03-26 and 2025-11-25 in `initialize`; return the negotiated version. Add a contract test for each.
- Middleware order: request-id → timing/EMF → auth (no-op when `AUTH_MODE=none`) → MCP app.

## 6. Auth spike (Day 9, 4-hour cap)

1. Cognito user pool + app client (authorization code, PKCE, refresh tokens, scopes `openid` + custom `nightwatch/tools`). Managed login domain.
2. Host `/.well-known/oauth-protected-resource` on the MCP host: `resource` = exact manifest URL, `authorization_servers` = [`https://<api>/auth`], `scopes_supported`.
3. Host `/auth/.well-known/oauth-authorization-server` (RFC 8414) yourself, pointing `authorization_endpoint`/`token_endpoint` at Cognito, with `code_challenge_methods_supported: ["S256"]`, `grant_types_supported: ["authorization_code","refresh_token"]`.
   VERIFY: the exact metadata URL Alexa derives from the issuer path, and whether Cognito tolerates the `resource` parameter.
4. Middleware: parse the JSON-RPC body. `initialize`, `notifications/*`, `tools/list`, and `resources/*` pass. `tools/call` without a valid Cognito JWT (JWKS-verified, aud/client_id, exp) → **401, JSON body, no `WWW-Authenticate`**.
5. `alexa-ai configure-account-linking --addon-id … --stage development --client-id …` → register **all** displayed redirect URIs in Cognito → `alexa-ai deploy`.
6. Map `sub` → household on first link (`USER#<sub>`).
Drop criteria: deploy still failing at hour 4 → revert to `AUTH_MODE=none`. Write it up as friction log + feature request ("first-class Cognito support / OIDC discovery").
